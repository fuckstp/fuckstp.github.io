# Cisco 基本PIM配置

> 别忘了底层需要单播支撑哦。

## 1. 静态RP

在PIM-SM模式中使用静态RP配置是组播域搭建的最简单方式。使用静态RP时，需要在域内参与相应ASM组转发的PIM路由器上配置一致的组到RP映射，包括源侧、接收侧、中间路由器和RP自身。

静态RP配合MSDP实现RP冗余的Anycast-RP在小规模网络中是个不错的选择。

### 1.1. IOS配置静态RP

## 2. 动态RP

### 2.1. Auto-RP(Cisco 私有)

如果不想逐台维护静态RP映射，可以使用动态RP发现。配置多个候选RP并保证底层可达，才能进一步提供冗余；也可以让不同组播组使用不同RP来分担负载。只把配置换成动态方式，并不会自动消除单点故障。
Auto-RP定义两个角色，但一台路由器可以既是MA也是CRP：

1. 班主任（MA，Mapping Agent），负责收集候选RP的公告，为组播组选择RP，再通过Discovery报文（224.0.1.40）把映射告诉其他路由器。可以部署多个MA提供冗余。
2. 班长（C-RP，Candidate RP），可以有多个，使用Announce报文（224.0.1.39）告诉MA自己愿意服务的组范围。对于同一组范围，MA选择地址较大的候选RP。

配置：
全局下使用 `ip pim send-rp-discovery <接口> scope <TTL>` 配置MA。
全局下使用 `ip pim send-rp-announce <接口> scope <TTL>` 配置候选RP，需要限制组范围时再加 `group-list`。

### 2.2. BSR（Bootstrap router）

BSR和Auto-RP都能动态分发RP信息，但分工不一样。候选BSR（C-BSR）先选出负责收集信息的班主任，候选RP（C-RP）向它报名。BSR把候选RP集合发给其他路由器，各路由器再按同一套规则为组播组选RP。

BSR选举先比较优先级，越大越好；优先级相同再比较地址，越大越好。Bootstrap报文通常发往224.0.0.13，由PIM邻居逐跳处理和传播。启动及失效接替涉及不同定时器，不能简单理解为固定等180秒就当选。

路由器收到Bootstrap报文后，会检查它是否从朝向BSR的RPF邻居收到，再按协议规则继续传播，防止环路。这里不是把224.0.0.13当作普通组播数据跨路由器转发。

当选BSR收集C-RP发来的单播公告，整理后放入Bootstrap报文。各路由器为某个组选择RP时，先取最长匹配的组前缀，再比较C-RP优先级（越小越好）、哈希值（越大越好），最后比较RP地址（越大越好）。收敛后，拿到相同候选集合的路由器才会得到一致结果。

配置：
全局下使用 ip pim bsr-candidate 接口（CBSR）
全局下使用 ip pim rp-candidate 接口（RPC）

### 2.3 Anycast-RP

MSDP是用来在RP之间传递活动组播源信息的协议，可以用于不同组播域之间，也可以用于同一域内的Anycast-RP。它告诉对端有哪些活动的（S，G），并不替接收者发送加入请求。

它和BGP一样，需要预先配置对等邻居，使用TCP 639端口传输。TCP提供可靠传输，但不等于报文自动获得加密保护。

源开始发送后，由源侧第一跳DR把组播数据封装成PIM Register发给RP。RP再通过MSDP SA（Source-Active）报文通告源信息。远端RP如果有这个组的接收者，就可以向源方向逐跳发送（S，G）Join，建立接收流量的路径。

MSDP实现Anycast-RP双主状态是常见的应用场景，IOS\IOS-XR\NX-OS三个平台都支持。

PIM Anycast-RP是另外一个实现方法，RFC 4610描述了通过PIM在RP之间共享注册信息的机制。具体到IOS、IOS-XR和NX-OS，要看设备、软件版本及地址族，不能只凭平台名称判断是否支持。

### 2.4 Phantom RP

Phantom RP用于BiDir PIM环境。BiDir不像普通PIM-SM那样依赖源注册，可以把一个没有实际配置在设备接口上的地址作为RP地址。不过，网络仍要有一致的组到RP映射、到该RP地址所在网段的路由，以及正常的DF选举，不能理解成随便填一个不存在的IP就行。

## 3. PIM SSM

SSM模型可参考RFC 4607，RFC 3569介绍了它的概念。PIM可以直接构建到源的树，不需要为SSM组配置RP。网络中可以有多个源，接收者按（S，G）选择通道；原生IPv4 SSM由支持IGMPv3的主机和应用表达源过滤需求。

SSM的特点是网络用户能够预先知道组播源的具体位置。因此用户在加入组播组时，可以明确指定（S，G）来接收指定源的流量。
接收端DR了解到用户主机的需求后，向源方向的RPF邻居发送（S，G）Join。Join逐跳向上传输，在源与组成员之间建立SPT。
例如下面两个（S，G）分别是两个通道（channel）：
A（S,G）=（1.1.1.1,232.1.1.1）
B（S,G）=（1.1.1.2,232.1.1.1）
就算两个源组播地址都是相同，接收方依然可以访问指定的channel，因为SSM是根据channel来区分组播流。在SSM模型中，PIM-SM的关键机制包括邻居发现、DR竞选、构建SPT。

IPv4 SSM使用232.0.0.0/8，本文的 `ip pim ssm default` 就启用这个范围。组播转发依靠到源的单播路由做RPF检查。

配置：

接收者连接的接口启用 `ip igmp version 3`，参与组播路由的接口启用PIM。

全局启用 `ip multicast-routing` 和 `ip pim ssm default`。

#### 3.1 IOS配置PIM-SSM

0.打通接口和IGP路由。这里的交换机使用同一VLAN的二层转发；下面只贴关键片段，Loopback0的 `ip address 1.1.1.1` 还应补上 `255.255.255.255` 掩码，其他接口地址按拓扑配置。

```
router ospf 1                                                                                         
 router-id [loopback-port-IP]                                                                                    
 network 0.0.0.0 255.255.255.255 area 0 
inter loopback 0
 ip address 1.1.1.1
 ip pim sparse-mode
```

1.启动PIM/IGMP version 3

```
ip multicast-routing
ip pim ssm default

interface Ethernet0/0
 ip address 192.168.1.1 255.255.255.0
 ip pim sparse-mode
 ip igmp version 3

```

2.指定加入组播和指定组播源

```
R1：
interface Ethernet0/0
 ip igmp join-group 232.1.1.1 source 2.2.2.2
R3：
interface Ethernet0/0
 ip igmp join-group 232.1.1.1 source 2.2.2.2
```

#### 3.2 IOS-XR配置PIM-SSM

1.接口加入IGMP，这里显式配置version 3，不依赖设备的默认值。

```
router igmp
 interface GigabitEthernet0/0/0/0
 !
 version 3

```

2.指定接收的组播源

```
router igmp
 interface GigabitEthernet0/0/0/0
  join-group 232.1.1.1 2.2.2.2
 !
 version 3

```

3.测试，需要指定源是2.2.2.2才可能成功。
